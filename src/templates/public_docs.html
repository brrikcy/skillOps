What is an API?

An API is a website for programs instead of people. Your Python code sends a request to an address (a URL). The server sends back a response: a status code and some data in JSON.

  • Method: what you want to do. GET reads data. POST sends data.
  • URL: the API address plus a path, for example {{ api }}/v1/whoami.
  • Headers: extra information sent with the request. Your API key goes in a header called x-api-key.
  • Parameters: options added after a ? in the URL, for example ?dataset={{ practice }}.
  • Status code: 200 means OK. 4xx means something is wrong in your request. 5xx means a problem on our side.

Before you start

  1. Register on the Register page with your join code. You get an API key.
  2. In your project folder, create a file called .env with the two lines from the Register page: 
    SIMLAB_API_KEY=rbk_your_key_here
SIMLAB_API_URL={{ api }}
  3. Add .env to your .gitignore file. Your key must never go to GitHub.
  4. Install two packages (Windows Command Prompt): 
    pip install requests python-dotenv

Never write the key itself inside your .py files. Read it from .env.

Your first API call

Ask the server who you are. If this works, your key and URL are right.

import os
import requests
from dotenv import load_dotenv

load_dotenv()                                   # reads .env into environment variables
API_URL = os.environ["SIMLAB_API_URL"]
API_KEY = os.environ["SIMLAB_API_KEY"]

response = requests.get(API_URL + "/v1/whoami", headers={"x-api-key": API_KEY}, timeout=30)
print(response.status_code)                     # 200 means OK
print(response.json())                          # the data, as a Python dict
curl -H "x-api-key: rbk_your_key_here" "{{ api }}/v1/whoami"

In PowerShell, type curl.exe instead of curl.

A good answer looks like this:

{
  "platform": "{{ live_data_name() }}",
  "student": {
    "name": "Asha Rao",
    "roll_number": "DA24-017",
    "batch": "DA-2026-A",
    "status": "active",
    "message": "You are approved. You can fetch data.",
    "registered_at": "2026-11-16T04:05:11Z"
  },
  "server_time": "2026-11-16T04:06:00Z"
}

If status is pending, your trainer has not approved you yet. Ask them, then call /v1/whoami again.

Purpose: get the rows that were released after since and up to now.

  "dataset": "{{ practice }}",

  "since": null,
  "until": "2026-11-16T05:30:12Z",
  "data_time_until": "2025-07-01 00:12:40",
  "columns": ["order_id", "order_time", "customer", "city", "amount", "quantity"],
  "rows": [
    [5001, "2025-07-01 00:00:00", "C417", "Pune", 1299.5, 2],

  • rows are lists, in the same order as columns. They are exactly the values in the source data.
  • null means SQL NULL. "" is an empty text. They are different. Numbers stored as text stay text. The data has deliberate defects. Finding them is your job.
  • until is the real UTC time this fetch covers up to. Save it. It is your next since.
  • data_time_until is the simulated business time (India time) at until.

since and until

The platform releases rows over time. Each row has a hidden release moment. A fetch returns the rows released after since and up to and including until. The server sets until to the time of your request.

fetch 1: since = ""                     until = 10:00:00  -> rows released up to 10:00:00
fetch 2: since = 10:00:00 (fetch 1's until)  until = 10:05:00  -> rows released after 10:00:00, up to 10:05:00
fetch 3: since = 10:05:00 (fetch 2's until)  until = 10:12:30  -> ...

Follow this rule and you will never miss a row and never get a row twice:

  1. Read the until of your last successful load from your own database.
  2. Fetch with that value as since (empty the very first time).
  3. Store the rows and the new until together, in one transaction.
  4. If anything fails, store nothing. Next time you will ask again from the same since.

All times in since and until are real UTC times, ending in Z. India time is UTC + 5:30.

Pages (pagination)

One response has at most 5000 rows. If more rows are waiting, next_page_token is not null. Ask again with page_token (and the same dataset) until next_page_token is null. Every page of one fetch has the same until. Save the until only after the last page.

all_rows = []
params = {"dataset": "{{ practice }}", "since": since}
while True:
    r = requests.get(API_URL + "/v1/fetch", headers={"x-api-key": API_KEY}, params=params, timeout=60)
    r.raise_for_status()
    data = r.json()
    all_rows.extend(data["rows"])
    if data["next_page_token"] is None:
        break
    params = {"dataset": "{{ practice }}", "page_token": data["next_page_token"]}
new_since = data["until"]          # save this with the rows
